# Bunny Loader C# — Dynamic runtime prototype (.45)

The baseline .43 remains stable. This experimental step tests a **compiled C# callback executed on demand inside the Terraria game process**, rather than a 120-sample trajectory or precomputed buff policy.

This **does not yet** make C# NPC AI, projectiles, draw hooks, or all ExampleModBunny APIs dynamic. The first checkpoint is whether MonoVM can initialize safely in the game's process and call a method from a **specific source mod's assembly**, repeatedly, retaining C# static state.

## What's changed

- The isolated MonoVM worker still compiles and validates source mods. No developer-side DLL or SO is required inside the .bmod.
- Its compiled output is now unique per mod: `files/bunny-csharp/compiled/<mod uid>.dll`. One mod no longer overwrites another mod's DLL.
- The game's MonoVM runtime is **not started automatically** by the new feature. A separate explicit in-process verification is required first. This is a deliberate safeguard because earlier in-process MonoVM tests caused process aborts on some devices.
- The native host caches the resolved `MonoMethod` per mod (maximum 16) and passes `tick` and `state` directly. The managed code is **executed on every call**, no precomputed curve.
- Managed exceptions/errors disable a mod's prototype after three failures. This is a prototype, not full managed-code sandboxing, unload support, or production error isolation.

## Controlled Android test

Install `BunnyLoader-CSharp-Test-v0.1.10.16.45-AutoSourceLoader.apk` and `ExampleModCSharp-v0.1.5.bmod` in a test environment. Enter singleplayer, then inspect:

```js
JSON.stringify(bl.csharp.sourceAutoStatus(), null, 2)
```

Wait for `applied: true` and `phase: "ready"`. The automatic worker should compile the updated example .cs files into a per-mod DLL. Do not use the live callback command before it finishes.

Check the **isolated worker** prerequisite. If needed, call:

```js
bl.csharp.managedProbe()
```

Wait until `bl.csharp.managedWorkerStatus()` shows its isolated test finished and the managed probe returned 42. This process does **not** prove game-process safety.

**Risk warning:** the next command deliberately loads MonoVM inside the Terraria process. It might crash the game, as previous attempts did. Back up test-world data, close other activities, and perform this only on an expendable test install:

```js
JSON.stringify(bl.csharp.managedGameProbe("CONFIRM_IN_PROCESS"), null, 2)
```

Only continue when its result has `phase: "verified"`, `domainInitialized: true`, and `result: 42`. If the game closes, report the crash logs **without proceeding to live callbacks**.

Run a dynamically executed C# method from the imported `ExampleModCSharp`:

```js
JSON.stringify(bl.csharp.sourceLiveTick("68c3115f-62f4-49f2-a56b-388256781d5f", 5, 10), null, 2)
```

Call the *same command a second time*.

The example uses a static C# variable `calls`; the expected first `lastResult` is **13**, and the expected second is **14**, with `callbacks` increasing from 1 to 2. This proves managed state persistence and direct invocation of a C# method with caller-supplied arguments.

Read the status without triggering another callback:

```js
JSON.stringify(bl.csharp.sourceLiveStatus("68c3115f-62f4-49f2-a56b-388256781d5f"), null, 2)
```

If the method or assembly is unavailable, read `phase` and `error`. The mod's DLL is not bundled in .bmod; it is generated by the isolated compiler. The game cannot hot-unload an assembly from its current Mono domain; restart after changing source files.

## Roadmap after successful Android verification

1. Extend the persistent host with per-mod instances and well-defined `Load`, `Unload`, `Update` lifecycle methods.
2. Add a safe state-struct API for selected NPC callbacks, using the already implemented `NpcAiHost.cpp` and `TerrariaHost.cpp` to copy current state into managed parameters and validate returned movement.
3. Measure per-callback latency, allocations, 60 FPS frame timing and crash recovery; never call Roslyn per frame.
4. Move from diagnostic entrypoints to the ExampleModBunny-equivalent C# class lifecycle and multi-mod dependency loader.

**Status:** GitHub smoke test validates C# callback semantics on a runner. Android in-game dynamic invocation is **unverified** until the explicit test above succeeds.
